### S1 办公任务先检查证据是否齐备

- 原帖：[立党办公 agent 资料前提](https://x.com/lidangzzz/status/2086770543206785383)
- 原站显示：2026-08-10 4:04，页面未标明时区；访问：2026-10-01
- 本轮通过云浏览器直接读到原帖正文与时间。此前资料只有未核实线索，本轮为正文覆盖补足
- 可采用的有限观点：办公 agent 依赖有组织、可取得的业务资料；不能假定未记录的信息能被可靠推断
- 排除：文中的机构群体概括、就业预测与百分比没有独立验证，不作事实或需求规模依据
- 用户需要（推断）：启动前知道关键资料缺什么、是否冲突，以及哪些决定必须询问责任人
- 最小功能（P0）：单任务必需证据清单，逐项标为已取得、缺失、冲突或无权读取；缺项时只阻塞依赖该项的动作
- 可执行验收提案：固定两份合成资料与必需字段；分别删除字段、注入冲突、撤销读取权限。预期分别返回缺失、冲突、无权读取，不得猜出一个值并标完成。补齐合法证据后，使用同一判据重新判断

### S2 GUI 只是有边界的可选接入实验

- 原帖：[立党关于 agent 接入界面的观察](https://x.com/lidangzzz/status/2103804274777936034)
- 原站显示：2026-09-26 4:10，页面未标明时区；访问：2026-10-01
- 本轮网页抓取未返回正文，云浏览器原站可读。是此前明确未核候选的覆盖补足
- 可采用的有限观点：作者认为 agent 可尝试直接使用图形界面。其机器人与模型能力例子为个人自述，本轮未验证
- 用户需要（推断）：旧工具没有合适接口时，评估是否存在可审查的窄接入路径
- 最小功能（P2）：保留稳定 API/CLI 优先；仅对一个已授权沙盒工具提供可关闭的 GUI 备选路径，记录目标、操作前提及独立结果判定。该路线选择是本研究建议，原帖没有给出
- 可执行验收提案：同一输入同一产物判据，分别测稳定接口可用、无接口、目标变化、操作后结果不可读四种情形；后三者不能靠界面上的“完成”字样自动判成功。不得操作真实账户、生产设备或机器人

### S3 外部资料的真实性与授权性分开

- 原论文：[AgentDojo v3](https://arxiv.org/abs/2406.13352v3)，[正文](https://arxiv.org/html/2406.13352v3)
- 首次发布：2024-06-19；本次版本：2024-11-24；访问：2026-10-01。是新增历史方法来源，不是 2026 年新论文
- 已读范围：摘要、§3.1 的状态/任务判定、§3.4 指标。论文将正常任务效用、攻击下效用和攻击成功分开评估，并以环境状态判定；不把论文旧模型分数转用于当前系统
- 用户需要（推断）：读进来的资料可以支持事实判断，但不能凭资料内的指令扩大操作权限
- 最小功能（P0）：来源和信任类别保留到工具调用边界；对越出用户任务的动作拒绝执行，并保留正常任务可完成性
- 可执行验收提案：在离线合成资料里放入要求转交额外数据的测试文本，以本地假工具记录动作；预期授权结果仍可交付、未授权动作数为零。单列正常任务成功率与攻击成功率，不能以“全部拒绝”冒充有效防护

### S4 终态正确仍不足以证明过程合规

- 原论文：[τ-bench v1](https://arxiv.org/abs/2406.12045v1)，[正文](https://arxiv.org/html/2406.12045v1)
- 首次发布与本次版本：2024-06-17；访问：2026-10-01。也是新增历史方法来源
- 已读范围：摘要、§3 的奖励与 pass^k、§5 失败分析。论文明确承认：数据库终态一致仍可能漏掉未获批准的操作；另区分多次尝试至少一次成功与多次均成功
- 用户需要（推断）：既知道结果是否完整，也知道过程是否越过授权，且能区分偶然成功与稳定交付
- 最小功能（P0）：结果判定与过程规则判定分栏，任一失败不得汇总成功；保留重复试验的每次记录
- 可执行验收提案：同一正确终态配两条轨迹，只有一条在修改前取得授权，预期另一条仍失败；两项请求只做一项也失败。重复试验前冻结任务、版本和预算；分别报告单次成功及全次成功，不挑最好的一次。这里增加的过程规则检查是本研究设计，不是声称原基准已解决该局限
