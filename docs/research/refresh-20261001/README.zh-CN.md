## 拟议验证顺序

1. P0：给一个窄工程任务冻结分母、审查与采纳规则；把未审查、错误和重复候选明确分开
2. P0：对该任务依赖的一个工具验证状态变化及不可读时的暂停行为，避免沿用过期前提
3. P1：在获授权试点中验证方案包的首次运行与失败接管，再考虑最小化的使用反馈数据

优先级是本研究的建议。指标模板、回执字段与合成事件都不能代替真实用户需求、运行时机制、独立领域判定或持续使用证据。
