## 汇总后的产品决策建议

| 优先级 | 具体问题 | 应交付的东西 | 完成证据 |
|---|---|---|---|
| P0 | 用户不知道结果是否可信 | 每个任务的验收项、产物与失败说明 | 独立验收及故意错误的拒绝测试 |
| P0 | 长任务中断后状态不明 | 可恢复状态与副作用核对机制 | 故障注入、恢复回执与重复执行统计 |
| P0 | 私有数据与工具权限不透明 | 数据边界、工具身份、访问策略和审计 | 脱敏审查、越权拒绝、供应链清单 |
| P1 | 现有工具互不衔接 | 一个CAD/网格/求解/绘图/验收的完整案例 | 同版本输入输出、解析或独立交叉验证 |
| P1 | 多Agent收益不清楚 | 同任务同预算的单Agent与并行比较 | 实际重叠、合格产物吞吐、总成本和人工复核时间 |
| P1 | 公开项目难以试用 | 中英文上手、明确依赖、可下载示例 | 全新环境复制命令成功，产物可核对 |
| P2 | 领域扩展引入重复系统 | 可选适配器和领域验证器 | 新工具只增加合同/转换/验收，不另造总运行时 |

所有优先级均为项目建议。当前是否实现、在哪个环境测试通过，必须查具体版本的能力清单；本文不把需求直接标记为完成。

## 展示主线

“给出一个科研或工程目标，交付可复核的成果，并清楚呈现时间、成本、失败和仍需人工判断的部分。”

实现顺序优先一个完整场景，再扩展任务数量、运行时间和设备规模。数百Agent是需要单独实测的目标；同时发起很多任务、展示很多窗口或生成很多文字，不足以证明吞吐和科学价值。

## 仍需取得的真实需求证据

- 研究人员：能否重放论文结果、定位失败参数、减少返工
- 工程团队：能否接入既有软件、部署边界和质量体系
- 开源使用者：能否快速安装、理解限制并复现实例
- 潜在付费组织：谁负责采购、验收条件是什么、持续使用价值是否成立

本轮没有进行访谈、联系机构或用户招募，也没有获得采购承诺。将公开观点转成具体功能与可检验假设，是研究的起点。
