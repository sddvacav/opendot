# OpenDot Engineering change request template

Draft template for a verified repository workflow. This file does not submit or publish a change.

## Problem and scope

Describe the problem, desired outcome, affected layer, and deliberately excluded work.

## Changes

Explain user-visible behavior, public interfaces, dependencies, and any changed permissions or data destinations.

## Verification

List the public version and environment, fixtures, actual commands, and results. Separate unit, integration, packaging, and end-to-end checks. Identify failed, skipped, and not-run checks explicitly.

## Failure behavior

Describe interruption, retry, cancellation, restart, cleanup, and duplicate-side-effect behavior where affected. Explain what remains unverified.

## Documentation and claims

Link updated examples, reference text, release notes, and [claim status](../docs/claim-status.md). Identify each new or expanded public capability statement and its evidence.

## Privacy and licensing

Confirm the exact outgoing files reviewed, fixture provenance, third-party licensing changes, and remaining findings. A checked template cannot replace review of the actual artifacts.

## Reviewer decision

Record required reviewers, open questions, accepted limitations, and the final decision using the project's confirmed process.
