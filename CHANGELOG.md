  and event-model 1.24.0; tested dependency recipe and upstream license attribution

- Explicit portable CI node manifest: the accepted 459-case combination plus 43
  Git/stdlib provenance cases, for 502 cases; no unrestricted full-suite invocation

### Fixed

- Actual-adapter Git membership is checked before recording local repository
  context. Ignored/untracked installed copies and uncertain contexts remain
  hash-only; inherited Git overrides cannot substitute another context
- New source records keep `worktree` null. Hidden or normalized source changes
  conservatively report dirty, and configured executable filters are not run
- Current test-selection links now lead to the current manifest and commands;
  both synthetic examples explicitly document their POSIX prerequisite

### Retained and clarified

- The already accepted optional operator-reviewed `SourceLock` admission API,
  synthetic qualification records, canonical source-audit helpers, and fake-only
  lab executable code remain unchanged. CAD/CAE changes are limited to the
  independently accepted provenance helper and actual-adapter call binding
- Default installation still has no required runtime dependencies or console
  scripts; simulation execution is opt-in and offline verification stays lightweight
- Bilingual capability descriptions distinguish simulated execution from the
  separate offline qualification-record checker; historical test scopes remain
  historical rather than being combined into a full-platform result

### Limits and migration

Existing source-record keys are retained, but new `worktree` values are always
null and `GIT_UNVERIFIED_SOURCE_HASH_RECORDED` is an additional fallback status.
Consumers must tolerate null commit/dirty/worktree on hash-only records; null
dirty means unknown, not clean. Historical receipts are not rewritten. Existing
default installs need no new dependencies. Opt into the exact simulation extra only when needed.
All scientific/device authority remains false; owner integration and per-run
independent review remain `NOT_EVALUATED`. There is no real hardware, general plan
endpoint, resume, scheduler, durable runtime, physical interlock, or publication
claim. Native CAD/solver, private-consumer, runtime/recovery/lifetime, model,
real-device, hosted-CI, and supported-platform acceptance are outside this update.
The Git-provenance correction is included; native evidence from earlier commits
does not transfer to this revision.
